## 现在的数据模型（定版，不是讨论过程）

参照音乐软件"收藏夹/歌单"：**一张事实卡本体只有一份，能同时归进任意多个文件夹**。取消了旧版（v1，`facts_store.py`/predicate 模式）的 multi/exclusive/historical 三模式和 `invalid_at` 失效机制，改成"每张卡最新时间点为准，旧的当历史"。v1 那套已经从 Dashboard 整个删除，时光馆是现在唯一入口。

- **`cards`（卡本体，稳定 id）+ `card_revisions`（时间线）**：一张卡的身份靠 id 认，不靠标题——标题能随便改，不会打散历史。最新 `valid_at` 的 revision = 当前状态，其余是历史。
- **`folders`（无限嵌套的树）+ `card_folders`（多对多）**：顶层 = subject（一澜/林湛/我们/…），下面可任意嵌套子馆。卡不绑定 subject，"属于谁"完全由归进了哪些文件夹体现。卡可以不属于任何文件夹（孤儿卡，允许）。
- **收藏**：两个固定馆——`一澜/收藏`（id `lan_only_for_zhan`）、`林湛/收藏`（id `zhan_only_for_lan`），`CardStore` 启动时自动建好。这两个馆**故意做成扁平的**，不能建子馆（后端强制拦截，三个入口——建馆 API、`card_create_folder`、Dashboard"+建子馆"按钮——都吃到同一处校验）。Dashboard 详情页两颗心图标、`card_favorite`/`card_unfavorite` 两个 MCP 工具都是奔着这两个固定馆去的。
- **协作写作**（一澜+林湛共同编辑同一张卡）：内容是"一段一段、每段自带作者"的结构（`content_segments`），显示成"一澜：……／林湛：……"。规则 C：自由**添加**内容永远不需要确认；**改/删对方写的段落**（含整段替换）需要走一次确认（`SegmentOwnershipError` → 前端/工具转成人话提示 → 传 `force=true` 才执行）。颜色：林湛 = `#264939`（Cypress Green），一澜 = `#044d78`（Pull Cyan Blue）。
- **合并（merge，数据清理工具）**：两张卡讲的是同一件事被误分开时用。**纯手动、确定性，不做自动重复检测**（吸取过批量导入的教训，不信任不可控的自动判断）。合并 = 时间线交错（改 `card_id` 归属，原始 revision 一个字不改）+ 标签/文件夹/记忆桶取并集 + 附件全保留不去重。旧 id 变成永久重定向指针（`_resolve_id` 全局透明解析，多级墓碑会拍平成一跳）。
- **历史批量导入：已彻底放弃**（2026-07-16，自动化质量一直不稳定，一澜决定改回纯人工创建）。原设计文档 `docs/batch-import-design.md` 已删除，完整记录在 git 历史里，删除前的版本可查。以后真要重拾这个方向，卡住过的真问题是"状态线压缩逻辑对连续创作历程类线索会压缩过头"。

## 已经做完、部署验证过的功能

- **数据层 + HTTP 层 + MCP 层 + Dashboard UI**（①②③④步）：`cards_store.py`/`cards_api.py`（19 条 `/api/cards-skeleton/*` 路由）/`cards_mcp.py`，"时光馆"是 Dashboard 里唯一的事实卡入口（动态多栏馆浏览、卡片详情、创建/编辑/New Revision、馆归属管理）。
- **给林湛的 MCP 工具**（`cards_mcp.py`，全部工具描述统一打了"【时光馆】"前缀方便他从一堆工具里认出这一批）：
  - 读：`card_lookup`（关键词/文件夹查卡）、`card_history`（一张卡完整时间线）、`folder_timeline`（一个范围内**全部卡的完整历史**交错成一条丝带，`folder` 留空 = 全部卡，50 条/页分页）、`folder_tree`（文件夹结构树，带卡数 + 收藏标记）、`card_buckets`（关联记忆桶详情）、`card_attachment_read`/`outline`/`view`（读附件文字/章节/看图，支持跨历史时间点用 `at=YYYY-MM-DD` 或直接按文件名找）。
  - 写：`card_create`/`card_create_folder`/`card_add_to_folder`/`card_remove_from_folder`/`card_favorite`/`card_unfavorite`/`card_edit_title`/`card_edit_tags`/`card_edit_content`/`card_new_revision`/`card_link_bucket`/`card_unlink_bucket`/`card_merge_preview`/`card_merge`。**没有** `card_delete`（等回收站机制）和附件上传（MCP 传不了二进制）。
  - `_resolve_folder`（所有带 `folder` 参数的工具共用）认精确 id、馆名、**以及完整路径**（"一澜 / 收藏"，带不带空格都行）。
- **收藏功能**（2026-07-18）：Dashboard 详情页两颗心（绿 = 林湛 / 蓝 = 一澜，点击切换，复用加/移文件夹接口）、浏览列表小心心（只显示真收藏了的）、林湛的 `card_favorite`/`card_unfavorite`、`folder_tree`。收藏馆固定排在同层级最上面。`ai_favorite`/Gateway 桥接**没做**——Gateway 还没搭，等搭好了单独立项，`identity.ai_name` 也还是默认值。
- **"丝带"——`folder_timeline` 的 Dashboard 视图**（2026-07-18）：馆浏览列表每行旁边一个小图标点开弹窗，横向时间线——每个历史时间点一个独立的点（不是每张卡只留一个代表点），当前状态的点深色大、历史点浅色小，标题按可用宽度动态换行/必要时省略号，日期两行（年 / 月日）。桌面端 Ctrl/Cmd+滚轮缩放（＋/－按钮兜底）+ 拖拽/滚轮平移；手机端双指缩放 + 单指滑动平移。点某个点开对应卡片详情。16:9 横版弹窗，思源宋体，短时间线/空馆提示居中。全站滚动条顺手统一改成了细的浅绿色样式。
- **附件能力**：`.docx`/`.pdf` 文字解析、图片查看（ChatGPT 连接器确认能渲染）、章节大纲解析 + 分页读取长文档、跨历史时间点/跨重名文件读取。图片/文件各自最多 10 个，类型加了 `.json`/`.py`。
- **搜索性能修复**（跟事实卡关联的部分，主体在 `bucket_manager.py`）：内存缓存 + embedding 双通道检索，解决了 7000+ 记忆桶规模下搜索拖垮服务器的问题；Add Bucket 精确 ID/标题命中会跳过模糊搜索。这块不是这份文档的核心话题，但直接影响事实卡"关联记忆桶"功能能不能用，记一笔。

### 踩过、别再踩的坑

- **FastMCP 的类型标注会在注册阶段崩容器**：`-> Union[str, Image]` 这种 pydantic 不认识的返回类型标注，会让 FastMCP 生成 schema 时直接崩溃、把整个容器带崩。新工具只要返回值可能不是 `str`/`bool`/`int`/`float`/普通 `dict`，部署前必须跑一次**真实 FastMCP** 注册冒烟测试（自建的 `FakeMCP` 测试测不出这个）。
- **别给林湛暴露内部 id 概念**：`segment_id` 暴露过一次，他压根没法用，后来整个撤掉改成"传完整新内容"。凡是要给他一个"定位到具体是哪个"的参数，优先用他自己能看懂、别的工具输出里本来就有的东西（比如日期、文件名），不要发明新 id。
- **不做自动矛盾检测/自动去重**：批量导入的教训是"自动判断错一次比省下的步骤更麻烦"，merge 工具做成纯手动确定性操作就是照着这条吸取的。
